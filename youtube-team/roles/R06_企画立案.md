# R06 企画立案

- 工程: 企画
- 上流: R01 市場調査、R02 競合調査、R04 トレンド調査、R05 視聴者分析、R27 改善提案
- 下流: R07 テーマ選定
- ユーザー承認: 不要（候補を出す段階。承認はR07のテーマ選定後にまとめて行う）
- 既存の実装: what-if-youtube/src/planning.py（plan工程）、what-if-youtube/config/prompts.yaml（1テーマから plan.json を作る。複数案の比較は未実装）
- 状態: 下書き（ユーザー回答待ち）

## 目的
リサーチ結果をもとに、動画企画の候補を複数（3〜5案）作る。長尺から派生させるShortsの候補も併せて出す。

## 責任範囲
### やること
- 企画案の作成（誰に・何を・なぜ今・どの柱・どの型で）
- 派生Shortsの候補（各案1〜3本の切り出し案）
- 各案のリスクやNG条件への抵触有無の自己チェック
- 前回の改善提案（R27）の反映

### やらないこと
- 案の最終選定（→R07）
- シーン・カット単位の構成（→R08）
- フックやセリフの作り込み（→R09・R10）

## 入力情報
- videos/<YYYYMMDD>_<slug>/01_research/ 一式
- rules/account.md（柱の配分）
- rules/ng_topics.md
- improve/ の採用済み提案（R27）

## 作業手順
1. ブリーフの目的・形式（長尺／長尺＋派生Shorts／単発Shorts）と、リサーチの要点を3行にまとめる
2. 企画案を3〜5個作る（テーマ指定があれば、その範囲内で切り口を変える）
3. 各案に、柱（A/B/C）と根拠となるリサーチ（ファイル名・行ID）を紐付ける
4. 長尺の案には派生Shorts候補を書く
5. 各案を rules/ng_topics.md で自己チェックする
6. 必要な素材（画面録画・顔出し・声・有料生成の有無）を各案に書き、ideas.md に保存する

## 出力形式
ファイル: videos/<YYYYMMDD>_<slug>/02_plan/ideas.md

```markdown
# 企画案（作成: R06）
## 案A: <一行コンセプト>
- 形式: 長尺 / 長尺＋派生Shorts / 単発Shorts
- 柱: A実験 / B解説 / C社会
- 対象ペルソナ:
- 視聴者が得るもの:
- なぜ今か（R04の根拠）:
- 型: 検証 / 比較 / 解説 / What If シミュレーション など
- 派生Shorts候補: 1) ... 2) ...
- 必要素材: 画面録画 / 顔出し有無 / 声 / 有料生成の要否
- NG条件チェック: 該当なし / 要確認（理由）
- 根拠: market.md §1, trends.md #2 など
```

## 完了条件
- [ ] 案が3個以上ある（テーマ固定時は切り口違い）
- [ ] 全案に柱・根拠・NGチェックがある
- [ ] 有料生成の要否が書かれている

## 次の担当への引き継ぎ事項
- R07へ: ideas.md と、推しの案があればその理由

## ユーザーへの確認が必要な場面
- 全案がNG条件の「要確認」に当たるとき
- ブリーフの目的が曖昧で案の方向が決まらないとき
- 共通: 判断に必要な情報が 【未確定：ユーザー回答待ち】 のままで、進めると結果が変わる場合
