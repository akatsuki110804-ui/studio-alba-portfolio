# 週次の分析レビュー（weekly-analytics-review）

状態: 下書き（ユーザー回答待ち）

## いつ使うか
- 週に1回（曜日: 【未確定：ユーザー回答待ち】）
- ユーザーが「最近の数字どう？」と聞いたとき

## 手順

1. **対象を決める。** 前回のレビュー以降に公開した動画と、記録タイミングに達した動画の一覧を作る（`publish_log.md`、YouTube制作台帳）。
2. **数値を集める（R26）。**
   - 取得方法: 【未確定：ユーザー回答待ち】（初期値: ユーザーにYouTube Studioの画面の数値を共有してもらう）
   - 使う指標は `rules/metrics.md` で「使う」になっているものだけ。現時点で決まっているのはShortsの「視聴を継続」。
   - 必ず「公開からの経過時間」と一緒に `metrics.csv` と制作台帳に記録する。取れない値は「未取得」。
3. **目標・基準と比べる（R26）。**
   - Shortsの「視聴を継続」: 目標70%以上（公式基準ではなく、よく言われる目安）。基準は月S2（旧レイアウト）の26.0%（1.5時間）／38.4%（約13時間）。
   - 経過時間がそろった値どうしで比べる。
   - その他の目標値: 【未確定：ユーザー回答待ち】（未設定の指標は達成・未達を書かない）
4. **コメントをまとめる（R25）。** 分類・件数・企画ヒント・事実の指摘。
5. **改善案を作る（R27）。** 企画／工程／ルールに分け、根拠と確からしさ（何本の結果か）を書く。1本だけの結果で断定しない。
6. **ユーザーに報告する（R28）。** 形式:
   ```
   今週のまとめ（YYYY-WW）
   - 公開: 長尺 n本 / Shorts n本
   - Shortsの「視聴を継続」: 動画名 xx%（公開からxx時間）… 目標70%に対して
   - コメントで多かったこと: …
   - 提案（採否を教えてください）: 1) … 2) …
   ```
7. **採否を記録する。** 採用された企画提案はR06へ、ルール変更は `skills/rule-update.md` で反映。

## 保存先
- `analytics/weekly/<YYYY-WW>/metrics_summary.md`, `comments_summary.md`
- `improve/<YYYY-WW>_proposals.md`
