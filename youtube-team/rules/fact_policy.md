# 事実・数値・出典の扱い（fact_policy）

最終更新: 未設定 / 更新方法: ユーザーが出典の条件（使ってよい／いけない情報源など）を決めたら、R28が `skills/rule-update.md` に従って追記し、変更履歴に1行足す。基本原則（1〜4）を緩める変更はユーザー本人の明示的な指示があるときだけ。

## 1. 根拠のない数値・事実は作らない

- 数値・統計・研究結果・固有名詞・日付・引用は、出典を確認できたものだけを使う。
- 「〜と言われている」「〜らしい」で根拠のない話を入れない。
- 推定・計算した値は「推定」「計算」と明記し、計算方法を残す。
- 既存の決定: **出典のない数字は使わない**（`docs/channel_plan_ai27.md`）。

## 2. 分からないことは「不明」と書く

- 調べても分からない項目は空欄にせず「不明」と書く。
- 画面に表示されていない数値（他チャンネルの非公開数値など）は「非表示」「非公開」と書き、推測しない。
- ユーザーの回答待ちの値は【未確定：ユーザー回答待ち】と書く。

## 3. 主張の種類を分ける

台本の主張には主張ID（C01〜）を付け、種類を分ける（既存パイプラインの research 工程と同じ考え方）。

| 種類 | 意味 | 台本での扱い |
|---|---|---|
| 事実 | 出典で確認できること | 確認済みなら使える |
| 推論 | 事実から考えたこと | 「〜と考えられる」など推論と分かる言い方にする |
| 演出 | What If の想定・たとえ | 想定であると分かる言い方にする |

## 4. 確認できない主張の扱い

R14の判定が「確認できない」「誤り」の主張は、次のどれかにする（G2でユーザーに確認）:
1. 削除する
2. 表現を弱め、推論・意見であることを明示する
3. 確認済みの別の事実に置き換える

公開後に誤りが分かった場合は、R28がユーザーに報告し、訂正方法（説明文・固定コメントでの訂正など）を相談する。

## 5. 出典の書き方

調査ファイル内:
```
[番号] タイトル / 発行者（著者） / URL / 発行日（分かれば） / 確認日
```
説明文（R24）:
```
出典:
・<発行者>「<タイトル>」(<年>)
```
- 論文は著者と年を書く（例の形式: 著者 年）。
- 一次情報（論文・公式発表・公的統計）を優先する。まとめ記事しかない場合は、その旨を書く。
- 使ってよい／いけない情報源の指定: 【未確定：ユーザー回答待ち】

## 6. 実験動画（柱A）の記録

- 実験の結果は、実際に行った手順・日時・使ったツールとバージョン（分かる範囲）を記録し、その記録の範囲で話す。
- 1回の実験の結果を一般的な結論として言わない。
